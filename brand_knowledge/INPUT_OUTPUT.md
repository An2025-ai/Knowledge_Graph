# L2/L3 知识图谱输入输出说明

> **版本**：1.0.0
> **日期**：2026-08-11
> **范围**：仅说明知识图谱搭建需要输入的资料和最终输出的信息

## 1. 整体关系

```text
L1 通用知识层：已建立的实体、关系、证据和质量规则
        ↓
L2 行业知识层：指定具体行业后，通过权威资料构建行业知识
        ↓
L3 品牌知识层：通过品牌官网和企业内部资料构建品牌知识
```

目标交付：

```text
PostgreSQL 权威知识数据
+ Neo4j 可查询知识图谱
+ 来源、证据、冲突、缺失项和审核报告
```

> 当前仓库只完成上述产物的数据契约、样例和部分 SQL。L2 基础表、Pipeline 执行器、Neo4j 投影服务和一致性报告尚未实现，因此这些是目标输出，不是当前可直接生成的输出。

## 2. L2 行业知识层输入

### 2.1 行业范围

| 输入 | 必需 | 示例 |
|---|---|---|
| 行业名称 | 是 | 电商业财一体化软件 |
| 市场区域 | 是 | 中国大陆 |
| 行业边界 | 是 | 面向中大型电商企业的业财融合软件 |
| 排除范围 | 建议 | 不包含个人记账和普通进销存软件 |
| 时间范围 | 建议 | 2023 至 2026 年 |
| 重点维度 | 是 | 用户、问题、能力、场景、决策因素、竞品、政策 |

### 2.2 行业资料

系统从以下权威资料中采集：

- 政府、监管机构和公共统计资料
- 国家标准、行业标准和监管文件
- 行业协会报告
- 权威研究机构报告
- 券商和咨询机构报告
- 学术论文
- 企业公告和权威媒体资料
- 厂商官网和公开产品资料，按厂商主张处理

当前不采集社区网站和普通 UGC。预设机构无法覆盖某个维度时，可以补充其他权威机构，但必须记录来源和选择理由。

每份资料至少保存：资料名称、发布机构、URL 或文件路径、发布日期、抓取日期、版本、适用市场、访问权限和文件 Hash。

## 3. L2 行业知识层输出

### 3.1 行业实体

- 行业和产品品类
- 市场参与者
- 用户角色和决策角色
- 用户问题
- Job to Be Done
- 使用场景
- 标准产品能力
- 购买决策因素
- 行业主题
- 政策、标准和监管主体
- 竞品和替代方案类型

### 3.2 行业关系

```text
行业 → 包含 → 品类
用户角色 → 面临 → 用户问题
用户角色 → 执行 → Job to Be Done
使用场景 → 需要 → 标准能力
品类 → 具有 → 决策因素
产品 → 属于 → 品类
```

### 3.3 行业知识交付

- 行业范围定义和来源清单
- 结构化行业报告
- 实体和关系清单
- 事实、统计、趋势和第三方主张
- 每条知识对应的原文证据
- 冲突、缺失维度和人工审核清单
- L2 行业知识快照
- PostgreSQL 行业数据
- Neo4j 行业子图

## 4. L3 品牌知识层输入

### 4.1 品牌基本信息

| 输入 | 必需 | 示例 |
|---|---|---|
| 品牌名称 | 是 | DeepCleer |
| 中文名和英文名 | 建议 | 深澈智算 / DeepCleer |
| 官方网站 | 是 | https://www.deepcleer.ai |
| 关联 L2 行业 | 是 | 电商业财一体化软件 |
| 所属公司 | 建议 | 上海智算云图科技有限公司 |
| 目标市场 | 是 | 中国大陆 |

### 4.2 品牌官网

建议采集：

- 首页和公司介绍
- 产品中心和产品详情页
- 解决方案页
- 客户案例和 FAQ
- 技术文档和下载资料
- 安全、合规和认证页面
- 服务支持和产品发布页面
- 联系方式和网站页脚

企业可以只提供官网主域名，由系统枚举站内页面；也可以直接提供指定 URL 清单。

### 4.3 企业内部知识库

| 建议上传资料 | 主要抽取内容 |
|---|---|
| 公司介绍 | 公司、品牌、定位和组织关系 |
| 产品说明书 | 产品、模块、能力、限制和版本 |
| 产品功能清单 | 品牌功能到 L2 标准能力的映射 |
| 架构和技术文档 | 技术、部署、集成和依赖 |
| 售前 FAQ | 客户问题、产品回答和适用条件 |
| 解决方案材料 | 用户、问题、场景和价值主张 |
| 实施和 POC 文档 | 实施阶段、周期和验收标准 |
| 安全与合规资料 | 权限、加密、认证和证书 |
| 客户案例 | 客户场景、结果和授权范围 |
| 服务和 SLA | 服务范围、响应时间和客户等级 |
| 套餐和定价资料 | 套餐、模块、部署和价格条件 |
| 品牌口径文件 | 允许、限制和禁止使用的表述 |
| 产品版本记录 | 产品版本以及能力上线和下线时间 |

支持 PDF、Word、PowerPoint、Markdown、Excel、HTML、图片和扫描件。

### 4.4 权限要求

每份文件需要指定：

```text
Public：可以公开使用
Internal：仅企业内部使用
Confidential：仅授权项目成员使用
Restricted：需要指定人员审批后使用
```

未指定权限的内部文件默认按 `Confidential` 处理。最好同时提供文件版本、更新时间、负责部门、当前是否有效、对应产品版本和是否允许对外引用。

## 5. L3 品牌知识层输出

### 5.1 品牌实体

- 公司或法律组织
- 品牌和品牌别名
- 产品、服务、产品版本和模块
- 内容资产
- 客户案例
- 认证和资质
- 来源、文档和证据

### 5.2 品牌到 L2 的映射

```text
品牌产品 → L2 产品品类
品牌产品 → L2 标准能力
品牌产品 → L2 使用场景
品牌产品 → L2 用户问题
品牌产品 → L2 用户角色
品牌内容 → L2 行业主题
```

例如：

```text
DeepCleer“虚拟店铺和法人抵消”
        ↓ 映射
L2 标准能力“多主体合并核算”
```

### 5.3 品牌 Assertion

输出以下带来源的陈述：

- 品牌身份事实和产品规格
- 产品能力、定位和价值主张
- 性能、规模和 ROI 主张
- 安全、合规和认证主张
- 实施、服务和 SLA 主张
- 客户案例和量化结果
- 内部事实和系统推断

官网和企业材料中的能力、性能、ROI、“领先”“首个”等信息默认按品牌自述保存，不能自动当作独立事实。

### 5.4 L3 知识交付

- 品牌来源、官网页面和企业文档清单
- 品牌实体和关系清单
- 品牌到 L2 的映射清单
- Assertion 和原文证据清单
- 文档版本、产品名称、数值和 SLA 冲突清单
- 缺失信息和人工审核清单
- L3 品牌知识快照
- PostgreSQL 品牌数据
- Neo4j 品牌子图
- PostgreSQL 与 Neo4j 一致性报告

## 6. 数据最终保存在哪里

### 6.1 PostgreSQL

PostgreSQL 是唯一权威数据库，保存：

```text
来源和原始文档记录
文档章节和 Evidence Span
实体、别名和关系
Assertion 及其证据
L3 到 L2 的映射
冲突、缺失信息和审核结果
权限、版本和知识快照
Neo4j 同步记录
```

### 6.2 Neo4j

Neo4j 是从 PostgreSQL 生成的图谱投影，展示：

```text
L2 行业共享节点
L3 品牌专属节点
L2 与 L3 的连接关系
实体业务关系
Assertion、Evidence 和 Source 节点
冲突和产品版本关系
```

知识修改先进入 PostgreSQL，再同步到 Neo4j。Neo4j 不作为权威编辑入口。

## 7. 最少输入要求

快速启动时，用户最少提供：

```yaml
industry:
  name: 具体行业名称
  market: 市场区域
  scope: 行业范围和排除范围

brand:
  name: 品牌名称
  official_website: 品牌官网
  related_industry: 对应 L2 行业
  internal_documents:
    - 产品说明书
    - 产品介绍或解决方案 PPT
    - 售前 FAQ
  default_access_level: confidential
```

如果 L2 行业知识已经存在，新品牌只需提交 `brand` 部分和企业资料，不需要重新构建整个行业层。

## 8. DeepCleer 示例

输入：

```text
行业：电商业财一体化软件
品牌：DeepCleer / 深澈智算
官网：https://www.deepcleer.ai
文件：QA、产品介绍 PDF、产品说明书 Markdown
```

输出示例：

```text
Organization：上海智算云图科技有限公司
Brand：DeepCleer
Product：AI 业财财报平台
Product：智能结算系统
Product：DCCLaw 桌面智能体

DeepCleer → OFFERS → AI 业财财报平台
AI 业财财报平台 → BELONGS_TO → 电商业财一体化软件
AI 业财财报平台 → HAS_CAPABILITY → 多主体合并核算
```

需要人工确认的示例：

- QA 文件名为 V2.1，但封面为 V2.0。
- DCCLaw 和 AI 智能体构建工厂是否为同一产品。
- 店铺规模出现 50 家以上和 100 家以上两种口径。
- 售后响应存在 15 分钟和 30 分钟两种表述。
- 等保三级、ISO 27001 和 ISO 27701 需要证书核验。

## 9. 验收要求

- 所有实体和关系都能追溯到来源。
- 品牌能力已经映射到 L2 标准能力。
- 品牌自述没有被错误标记为独立事实。
- 文档版本、产品名称和数值冲突已经记录。
- 内部资料权限没有在图谱同步中丢失。
- PostgreSQL 中存在完整权威记录。
- Neo4j 可以从 PostgreSQL 当前快照重新构建。
- PostgreSQL 与 Neo4j 的实体、关系和 Assertion 数量一致。
