# 行业与品牌研究：搜索、爬取、社区抽样及引用完整规范

- 版本日期：2026-08-07
- 适用范围：GEO、AI 搜索、品牌营销，以及其他行业的市场规模、用户痛点、竞品、融资、投资趋势和产品需求研究
- 执行原则：先保存原始证据，再进行模型归纳；搜索结果摘要只用于发现，不作为报告证据
- 当前本地搜索入口：`http://127.0.0.1:8080`（SearXNG）

## 一、研究启动前必须定义

每次研究先记录以下内容：

1. 研究主题、涉及行业和具体产品。
2. 地理范围，例如中国大陆、全国、某城市或海外市场。
3. 决策对象，例如品牌负责人、市场、电商、采购、产品、法务或投资者。
4. 需要回答的问题：市场、用户、竞品、产品、定价、融资或趋势。
5. 当前自然年和证据时间窗口。
6. 需要重点核验的公司、产品、数字、案例和争议。

## 二、时间范围

1. 优先检索和采用当前自然年的材料。
2. 当前年证据不足时，回退至此前 24 个月，并在报告中标注日期回退。
3. 更早材料只用于定义、法规沿革、学术基础和长期对比。
4. 产品功能、价格、融资和公司状态必须以当前可核验页面为准。
5. 不得用旧市场规模预测冒充当前实际规模。

## 三、强制来源层级与网址清单

所有适用来源都必须搜索。没有相关结果、受阻或不适用，也必须记入覆盖台账。

### 3.1 用户不知道权威信源时的自主发现规则

用户不需要提前提供网站清单。研究系统必须主动识别该行业在中国和海外的权威数据发布方，完成核验后再爬取。

#### 发现顺序

1. 政府部门、监管机构和国家统计机构；
2. 官方标准组织和国际组织；
3. 行业协会、交易所和法定信息披露平台；
4. 有公开方法的研究机构、大学研究中心和权威数据库；
5. 上市公司公告、财报和产品原始文档；
6. 有采编和调查能力的可靠媒体；
7. 社区和用户内容，仅用于补充真实表达。

#### 中英文发现查询

除固定来源清单外，至少追加以下查询类型：

```text
主题/行业 + 权威机构 + 官方统计 + 行业协会 + 研究报告 + 当前年份
主题/行业 + 政府 + 监管 + 标准 + 白皮书 + 数据 + 当前年份
TOPIC + authoritative institution + government statistics + industry association + report + YEAR
TOPIC + official dataset + regulator + standard + methodology + YEAR
```

从可信报告的脚注、参考文献和数据来源继续追溯，直到找到原始数据所有者或原始发布机构。优先引用原始报告、数据集、公告或方法页，不引用转述文章代替原文。

#### 权威性核验

候选网站至少核验：

- 机构法律/公共身份及职责；
- 域名是否为机构正式官网；
- 作者、研究团队和发布日期；
- 样本、范围、数据来源和研究方法；
- 是否披露资助、客户或商业合作关系；
- 是否能获得原始报告、原始数据或正式公告；
- 是否被其他独立权威来源合理引用或交叉印证。

搜索排名靠前、被多家媒体转载、使用 `.org`/`.com` 域名、页面制作精美或自称“权威”，都不能单独证明权威性。

#### 采用与披露

1. 关键市场或用户结论尽量同时取得一个国内原始/成熟来源和一个独立交叉来源。
2. 没有合适的国内或国际对应来源时，说明缺口，不得为了“国内外都有”而使用低质量网站。
3. 新发现来源必须进入搜索覆盖清单，记录发现查询、机构类型、权威性理由、访问状态、是否采用和局限。
4. 排除获客站、复制数据站、无出处图表、合成排行榜，以及无法验证发布机构或研究方法的报告。
5. 自主发现用于补充固定必查清单，不能替代或跳过后续列明的强制来源。

| 行业垂直媒体 | 36氪 https://36kr.com/；虎嗅 https://www.huxiu.com/；Morketing https://www.morketing.cn/；梅花网 https://www.meihua.info/ |

### 第三层：竞品、公司和最新资讯

对每个重要竞品至少核查：

1. 官方首页和产品页。
2. 定价、套餐、试用和计费说明。
3. 帮助文档、API、数据导出和集成说明。
4. 客户案例、新闻中心、博客和公众号公开文章。
5. 公司主体、备案或工商信息，必要时核验。
6. 融资、并购、合作和产品发布的原始公告。
7. 信通院、艾瑞、爱分析、头豹、36氪、虎嗅、Morketing 等第三方报道。

融资和重大合作必须同时寻找“公司原始公告 + 可靠独立报道”。无法读取报道正文时，不引用融资金额、轮次和投资方。

竞品信息必须分为：

- 官方产品事实；
- 第三方观察；
- 厂商自报案例；
- 独立验证结果。

匿名案例、厂商排行榜和客户效果自述不得写成独立验证事实。

记录券商、分析师/团队、报告标题、日期，以及实际读取的是全文还是摘要。券商预测属于情景判断，不是已发生事实。东方财富是检索入口，必须核验报告真实发布机构。

### 第五层：补充来源

只有在完成国内强制来源搜索后，或来源具有独特证据时补充：

- 政府和监管：网信办、市场监管总局、工信部、法院、标准组织；
- 学术：arXiv、ACM、ACL Anthology、Google Scholar、知网、万方；
- 国际研究与产品：Gartner、Forrester、Similarweb、Statcounter、G2、Capterra、Product Hunt、Reddit、TechCrunch、公司财报和官方文档；
- 技术和开发者信号：GitHub、Hacker News、官方 issue 和文档。

## 四、SearXNG 搜索要求

1. 每个必查域名分别执行 `site:DOMAIN 主题词 行业词 当前年份`。
2. 行业和品牌调研至少覆盖以下查询家族：
   - 市场规模、用户规模、增长和渗透率；
   - 用户痛点、评价、投诉、风险和避坑；
   - 产品、功能、价格、案例和服务模式；
   - 竞品、融资、合作和最新发布；
   - 券商、研报、投资和长期趋势；
   - 监管、法律、标准和学术证据。
   - 国内外权威机构、官方数据、行业协会和方法公开的数据源发现。
3. GEO 调研增加：`AI搜索`、`生成式引擎优化`、`AEO`、`GEO服务商`、`效果监测`、`ROI`、`归因`、`投毒`、`合规` 等词。
4. 其他行业沿用同一来源清单，只替换行业、产品、品牌和用户场景关键词。
5. 搜索结果页和摘要只用于发现候选页面。报告引用必须指向已打开的原始网页。
6. 每条查询保存：查询式、目标域名、搜索时间、结果数量、候选 URL、采用状态和失败原因。
7. 不得因为某域名没有结果就从覆盖清单中删除。

## 五、网页打开与爬取要求

1. 使用原始页面、官方 PDF、报告图表或正式公告作为证据。
2. 每条采用记录至少保存：
   - 标题；
   - 发布机构/作者；
   - 发布日期；
   - 原始 URL；
   - 搜索查询；
   - 访问状态；
   - 引用原文或使用的事实；
   - 样本、范围和方法；
   - 证据等级；
   - 局限。
3. 记录 `searched`、`used`、`no relevant result`、`login/paywall`、`blocked`、`partial` 或 `not applicable`。
4. 登录墙、验证码、付费墙、robots.txt 和平台访问限制不得绕过。
5. 中国信通院 412、QuestMobile robots、头豹正文过短等情况应改用人工浏览或报告为受阻，不能用搜索摘要代替原文。
6. 页面只返回标题、导航、软 404 或极短正文时，不得记为成功采集。
7. 重要事实尽量由两个独立来源类型交叉验证。

## 六、知乎和小红书强制抽样规则

这些数量是定性目的性抽样的最低门槛，不代表总体统计样本。

| 平台 | 每个查询的候选池 | 最低有效帖子 | 最低有效评论 |
|---|---:|---:|---:|
| 知乎 | 检查前 20 条结果 | 8-12 个页面 | 合计至少 15 条 |
| 小红书 | 检查前 20 条结果 | 12-20 篇笔记 | 合计至少 20 条 |

### 6.1 查询要求

每个平台至少使用四类查询：

1. 行业/品类/产品关键词；
2. 采购、服务商、选型、哪家好；
3. ROI、效果、监测、归因、转化；
4. 投诉、踩坑、骗局、风险、合规、避坑。

垂直行业还需加入行业名称、目标用户、消费场景和监管词。

### 6.2 有效帖定义

帖子正文或评论区至少贡献一项与研究相关的内容，才计为有效帖：

- 真实经历或使用结果；
- 具体业务问题；
- 明确反对意见或反例；
- 清晰使用场景；
- 选型或验收标准；
- 可执行产品需求。

### 6.3 有效评论定义

有效评论至少包含一项：实际经历、角色/行业背景、业务场景、因果解释、明确异议、反例或可执行要求。

以下内容不计为有效评论：

- 求联系方式、求资料、求分享；
- 表情、单字、泛泛赞美；
- 服务商自荐和私聊引流；
- 复制的排行榜、固定 ROI 或固定见效承诺；
- 明显 AI 摘要或结构化复述；
- 无法追到原始事实的案例数字。

优先读取较长评论和展开楼中楼，但长度不是唯一标准。

### 6.4 样本结构

有效帖子应尽量覆盖：

- 直接用户/采购方提问；
- 负面经历或失败案例；
- 从业者解释；
- 观点分歧和反例；
- 高互动帖子与低互动高信息量帖子。

不能只选正面内容，也不能按互动量直接排序为证据强弱。

### 6.5 停止和未达标规则

1. 原则上达到平台最低有效帖和有效评论数后才能停止。
2. 只有连续检查 5 篇候选帖没有新增主题，且上述证据角色已经覆盖，才允许按“主题饱和”提前停止。
3. 提前停止时必须记录这 5 篇候选帖及其未新增主题的原因。
4. 因登录、验证码、删除、搜索质量或缺少相关讨论无法达标时，报告实际检查数、有效帖数、有效评论数和阻碍原因。
5. 未达最低数量的平台必须标为 `partial`，不得改小门槛或声称完整覆盖。

### 6.6 平台披露字段

报告必须披露：查询词、可见排序/筛选方式、检查候选数、保留有效帖数、有效评论数、排除类型、停止原因、抽样偏差和每篇保留帖的原始 URL。

## 七、知识星球规则

知识星球不设置固定帖子数或评论数。使用时只记录：

- 访问了哪些圈子；
- 打开多少主题；
- 实际看到多少成员评论；
- 内容是否高度集中于圈主；
- 登录、权限和付费限制。

圈主内容属于供应侧或运营者第一方观点。没有独立成员评论时，不能写成用户痛点或品牌方共识。

## 八、登录和浏览器要求

1. 当前项目需要登录的重点平台为知乎和小红书。
2. 用户在专用 Edge 会话中自行输入账号、密码、短信验证码或扫码。
3. 不要求用户把密码、验证码或 Cookie 发给研究人员或模型。
4. 不读取日常浏览器 Cookie；只复用用户明确控制的已登录会话或项目专用 profile。
5. 出现验证码、二次验证、频率提示或授权页时停止自动流程，由用户处理。
6. 登录状态不能访问正文或评论时，必须如实标为受阻或部分覆盖。
7. 只执行低频、只读采集，不发帖、不评论、不点赞。

## 九、证据等级

| 等级 | 定义 | 使用方式 |
|---|---|---|
| A | 政府统计/法规、官方备案、可复现原始数据、同行评审学术证据 | 可支持关键事实，仍需说明口径 |
| B | 有方法、样本、日期和范围的研究机构报告或可靠调查报道 | 可支持主要市场和需求判断 |
| C | 官方产品、价格、公告和具名公司陈述 | 只证明官方声称或当前功能 |
| D | 社区帖子、互动信号、厂商匿名案例、未经审计的从业者观点 | 只作方向性声音和假设发现 |
| E | 无原始来源、误归属、复制榜单、合成汇总或无法核验声明 | 排除出结论；必要时列入 rejected claims |

搜索摘要、厂商软文和匿名案例不得替代已打开并核验的原始证据。

## 十、账号和内容身份分类

社区内容至少区分：

1. 疑似真实用户/采购方；
2. 行业从业者；
3. 服务商或产品官方账号；
4. 媒体、研究者或专家自述；
5. AI 摘要/问答账号；
6. 身份无法判断。

身份无法独立核验时必须明确说明。服务商观点可以用于观察市场话术和产品供给，不能作为客户效果证据。

## 十一、模型归纳要求

1. 原始搜索结果、网页正文和社区评论必须先保存，再调用模型。
2. 模型只能依据已经归档、带原始 URL 的证据归纳。
3. 模型输出必须区分用户、从业者、厂商、媒体和 AI 摘要。
4. 模型不得把社区评论解释为总体比例，不得补造样本、时间、ROI 或因果关系。
5. 模型生成的每项结论必须人工回查证据；不能回指原始来源的内容必须删除。
6. 记录模型名称和用途，不得把模型总结列为独立信源。
7. 对模型生成但被拒绝的关键声明，在 `rejected claims` 中说明原因。

## 十二、引用要求

1. 每条事实、数字、比较、产品能力、用户原话和市场判断后紧跟可点击的原始网页 URL。
2. 不允许只在文末集中列链接而正文无对应引用。
3. 不引用 SearXNG 结果页、搜索摘要或无法打开的候选页面。
4. 数字必须注明日期、样本/人群、范围和方法；无法获得时说明局限。
5. 产品价格和功能优先引用官方页面。
6. 用户评论引用保留原话、作者显示名、日期、互动量和帖子直链；身份不可核验时标为 D 级。
7. 每个主要综合判断后写明依据的来源类型和网址，例如：

```markdown
**判断依据：** 艾瑞用户调查 + 央视调查报道 + 小红书采购评论 + 3 家竞品官网。
[艾瑞](URL) [央视](URL) [小红书](URL) [竞品1](URL)。
```

## 十三、报告必须包含的结构

1. 研究范围、对象、日期和证据规则；
2. 执行摘要；
3. 市场规模和背景；
4. 用户痛点与真实表达；
5. 品牌/客户评价维度优先级；
6. 产品核心卖点与功能需求；
7. 竞品全景、定价、案例和资讯；
8. 投资视角与长期趋势；
9. 矛盾证据、研究局限和 rejected claims；
10. `搜索覆盖清单`；
11. `完整信源清单`。

完整信源清单字段：

`编号 | 层级 | 机构/作者 | 标题 | 日期 | 搜索查询 | 原始网址 | 访问状态 | 使用的事实 | 证据等级 | 局限`

搜索覆盖清单必须逐个列出强制域名，并标记已搜索、已采用、无相关结果、登录/付费、受阻、部分覆盖或不适用。

## 十四、禁止事项

- 用搜索摘要代替原始网页；
- 用厂商软文或匿名案例证明效果；
- 把互动量当作需求比例；
- 把服务商自荐当作用户反馈；
- 引用无法核验的市场规模、转化率和厂商排行榜；
- 承诺“固定 ROI”“几天见效”“永久前三”；
- 将券商转载、企业报告或聚合页冒充券商原始研报；
- 绕过登录、验证码、付费墙、robots.txt 或访问控制；
- 暴露 API Key、密码、验证码、Cookie 或本地登录资料；
- 在没有打开原文时写入事实。
