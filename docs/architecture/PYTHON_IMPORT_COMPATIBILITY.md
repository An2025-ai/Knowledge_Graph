# Python 内部导入兼容政策

## 适用范围

本政策适用于 Brand Atlas 仓库中的 `backend.app` Python 模块。`backend.app` 是桌面 Sidecar 的内部实现边界，其模块路径、包层级和构造方式不承诺长期稳定。

## 目录调整影响

R1—R8 目录整理可能改变直接导入旧模块路径的调用者。仓库内的测试、脚本和运行时代码会随迁移同步更新，但仓库搜索无法证明不存在外部或私有调用者，因此不宣称没有外部调用者。

已知直接导入旧路径的私有调用者应更新到当前路径。不要依赖 `backend.app` 内部模块作为第三方公共 SDK。

## 稳定调用边界

桌面端的主要调用边界是本地 HTTP API。调用者仍需遵守 API 的版本约定、请求和响应契约，以及会话鉴权要求；本地运行不等于绕过这些约束。

## 兼容入口策略

只有在发现具体且有明确迁移窗口的兼容需求时，才提供限期兼容入口。兼容入口必须记录调用者、截止版本和移除计划，不恢复所有历史模块路径，也不复制一套业务实现。

当前没有为未知外部调用者恢复旧路径 re-export。历史可视化工具已归档到 `legacy/visualize/tools/`，它不是新版运行时或稳定 Python API 的一部分。

## 维护原则

- 新功能通过 HTTP API 或明确的 Application 用例边界接入。
- 需要内部导入的仓库代码应在目录迁移时同步修正并通过测试。
- 发现真实兼容需求后，先补充调用样例和测试，再决定是否提供临时入口。
